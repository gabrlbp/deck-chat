2 Quem faz o quê

Renderer · Svelte 5

src/renderer
  • Desenha só a moldura: barra, cabeçalhos, status
  • Mede cada slot e manda os bounds ao main
  • Fala só com window.deck

Main · SlotManager

src/main/slots
  • 1 WebContentsView por slot
  • persist:slot-N = navegador separado
  • backgroundThrottling: false
  • Mutar, recarregar, auto-reload em crash

Main · TwitchPresence

src/main/twitch
  • Device Code Flow, scope chat:read
  • 1 WebSocket IRC → JOIN em todos os canais
  • PING/PONG, reconexão, refresh do token
  • Mensagens descartadas: só presença
Svelte→preload (IPC validado com Valibot)→main→pokeidle.io ×4+irc-ws.chat.twitch.tv

3 Decisões principais

Runtime
Electron

Partitions isolam as sessões nativamente. Tauri/WebView2 brigaria com vários perfis.

UI
Svelte 5, sem Kit

Runes ≈ signals do Angular. Sem rotas nem SSR: é um app de uma tela.

Validação
Valibot

Só nas fronteiras: config em disco, IPC, OAuth. Não é exigência do Svelte.

Twitch
IRC headless

Presença no chat, que é o que o Get Chatters (do mod/dev) enxerga. Custo ~0.

Segredos
safeStorage

Token Twitch criptografado com a DPAPI do Windows.

Configurações
Aba + modal com foto

Os slots são escondidos (o jogo segue rodando) e o modal aparece sobre prints desfocados.

Distribuição
1 repo privado, update manual

CI gera o .exe nos Releases com o GITHUB_TOKEN automático. Sem PAT, sem segundo repo.
